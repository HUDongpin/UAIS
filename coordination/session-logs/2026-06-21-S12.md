## External Storage Health Contract Fix

### Scope

- Took a focused S12 backend/API package after S22 production checks showed the deployed external-storage health route returned an empty HTTP 500 on `www.uais.top`.
- Did not inspect, print, or modify real secrets.
- Did not mutate Vercel env or deploy.

### Root Cause

- `createExternalStorageHealthGetHandler` called `probeDurableBackingStore`.
- `probeDurableBackingStore` only caught failures after `.health-probes` directory creation and probe path setup.
- If directory creation/path probing failed, the exception escaped the route handler, producing a generic server failure instead of the redacted external-storage readiness contract.

### Completed

- Added a TDD regression in `tests/external-storage-next-route.test.ts`:
  - A failing durable backing-store probe must return HTTP 503.
  - The response must keep `cache-control: no-store`.
  - The response must include `apiContractVersion`, `productionServiceIdentity`, `durableBackingStore.status=blocked`, and redaction metadata without leaking the token or local path.
- Updated `src/lib/server/external-storage-route-service.ts` so the whole durable probe is inside the redacted failure path.
- Saved S22/S12 evidence:
  - `coordination/reports/2026-06-21-external-storage-www-uais-top-health-blocker-and-contract-fix.json`
