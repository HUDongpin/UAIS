## Adversarial review round (post-implementation)

A multi-agent review ran over the change set (two of four lenses completed before the session's subagent limit; all findings then verified manually against the code). Confirmed and fixed:

1. Per-slide narration-finish carried `result.completion: true` while tagged with the manifest lesson id — one finished slide would have marked the whole lesson complete in learner profiles (the 412a52c bug class). Fixed: per-slide events now carry duration only; lesson + course completion comes solely from the all-slides `course.completed` (which now also carries `lessonId`).
2. Learner-profile `readLessonId` fell back to the last activity-path segment for ANY statement, so checkpoint/AI-guide/chatroom events would have minted phantom "lessons" and dragged `completionRate` down. Fixed: the fallback now applies only to lesson-typed activity objects; study events additionally carry the real `lessonId` when a manifest is loaded.
3. Approved-invite `classId` could be stamped onto statements about a different course. Fixed: classId is attached only when the invite context's course matches the event's course.
4. `course.completed` only fired within one page load. Mitigated: per-slide completion progress persists in device localStorage per learner/course/manifest (server-side aggregation remains the durable follow-up).
5. Tenant-stamped re-POSTs of pre-deploy deterministic statement ids would 409 and burn 3 retries. Fixed: the recorder treats a same-id 409 as an already-stored idempotent write (`LrsWriteError` carries the HTTP status).
6. Script paging hardened: empty page, unparseable `more` link, or a repeated page URL now ends pagination instead of looping.
7. Runbook now warns that same-provider/different-store targets need `--allow-same-endpoint`, and documents the shared-store analytics limit-before-filter caveat.

Acknowledged, not changed (by design): chatroom events attribute to the published course and 403-drop for non-members; a pre-approval 403 suppresses identical deterministic-keyed events until the next page load; shared-store foreign statements can starve limited analytics reads until the dedicated-instance migration lands.
