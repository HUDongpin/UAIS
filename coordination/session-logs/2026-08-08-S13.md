## Summary of work completed

1. **Group management panel** in the course-settings workspace. Each course card now carries a
   `小组协作 | Group Collaboration` panel (`data-uais-learning-group-panel="<courseId>"`) that lists
   the persisted groups of that course with member chips, the owning class (or `全课程 | Whole course`),
   an `旁听 | Observe` deep link to `/learning/chatroom?courseId=…&groupId=…`, plus edit and
   two-step-confirm delete entries. Create/edit uses one dialog following the existing
   `NewClassDialog` pattern (overlay, `role="dialog"`, Escape-to-close, submit-time error alert).
2. **Handlers** live in `src/components/teaching/use-teaching-learning-groups.tsx` and are re-exported
   from `use-teaching-workspace.tsx`. Every mutation follows the established
   `createClassForCourse` / `approveClassMembership` contract: mutate → verify the persisted receipt
   names the requested action and course → re-read `GET /api/teaching/courses` → verify the readback
   actually carries the change (name, member set, or absence on delete) → only then reconcile state
   and publish a success status. A failed verification throws a localized message that the dialog
   renders instead of a false success.
3. **Member picker** offers approved membership rows only, filtered to the selected class when the
   group is class-scoped, and mirrors the server's 2..12 bounds client-side (submit stays disabled,
   with the min/max guidance rendered inline).
4. **Server validation reason codes** (`group-name-required`, `group-members-required`,
   `group-members-below-minimum`, `group-members-above-maximum`, `group-member-duplicate`,
   `group-member-invalid`, `group-member-not-approved`) and the `teacher-course-ownership-required`
   access denial are mapped to friendly bilingual messages.
5. **Student dashboard Group Signal card** renders the real student projection (group name,
   co-member display names, self marked with `我 | you`) and deep-links to
   `/learning/chatroom?courseId=…&groupId=…`. It rides the dashboard's existing single
   `GET /api/teaching/courses` — no extra request. With no group, the previous placeholder card stays.
6. **Students operation page data** now states that chatroom groups are created and edited in the
   course-settings Group Collaboration panel, and records that group suggestions are review-only and
   never auto-assign students.

## Assumptions

- The Phase 1 group API is frozen; no `src/app/api/**` or `src/lib/server/**` file was touched.
- Whole-course is the create default (no `classId` sent); a class-scoped group is chosen explicitly
  and then only that class's approved students are assignable, mirroring the server lookup.
- `PATCH` cannot move a group between classes, so the edit dialog does not offer the class select.
- Deleting a group retains its transcript server-side; the UI says nothing about transcript loss.

## Risks

- The panel loads groups on first open rather than on page mount. This was deliberate: an eager
  second `GET /api/teaching/courses` on `/teaching` would have changed the request count that
  existing teaching-page tests pin. Consequence: a teacher clicks `管理小组 | Manage groups` once per
  session before seeing group counts. Folding the group readback into the page-level readback needs
  `teaching-page.tsx` prop threading, which is outside this package's write scope.
- The group panel is not feature-flag gated. `UAIS_LEARNING_CHATROOM_GROUPS_MODE` only gates group
  chatroom rooms; the group CRUD API is not flag-gated, so a teacher can create groups while the
  chatroom flag is off, and the observer deep link then falls back to the legacy room silently.
- Observed once, not caused by this package: `tests/learning-chatroom-group-live.test.tsx` >
  "resolves a ?groupId= deep link without the link naming the course" failed a single time under
  heavy parallel load (`expect(reads).toHaveLength(1)` saw 2 history reads). The suite uses real
  timers and the chatroom polls every 5s, so a slow run can slip a second poll in before the
  assertion. Ten subsequent runs, including two full-suite runs, were green. Flagged for S04/S11 —
  chatroom files are outside this package's write scope.
