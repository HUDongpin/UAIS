## Implemented

- `GET /api/teaching/courses/[courseId]/collaborators` lists the safe,
  address-free grant projection for a signed teacher app session. Canonical
  course-owner authority remains enforced transactionally by the Postgres
  store.
- `POST /api/teaching/courses/[courseId]/collaborators` requires matching app
  and teacher write sessions, an explicit idempotency key, a bounded JSON body,
  and a valid course id. It returns 201 for a persisted grant and 200 for an
  already-active replay.
- `DELETE
  /api/teaching/courses/[courseId]/collaborators/[grantId]` requires the same
  dual-session identity and an explicit idempotency key before revocation.
- Invalid role/session/path/body/idempotency inputs stop before the injected or
  real store is called.
- Typed store errors retain only HTTP status and stable `reasonCode`.
  Arbitrary store details, exception messages, submitted email addresses,
  secrets, and credentials are not echoed.
- Missing isolated-staging database configuration fails closed with
  `503/core-database-required`; no local JSON fallback is introduced.
- Collection and item route modules expose only Next-supported exports and use
  Promise-valued dynamic route params.
