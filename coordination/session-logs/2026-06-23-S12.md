## Handoff Update

- Completed route hardening for `/api/teaching/operations`: signed teacher auth is required, request body `actorId` is ignored, the signed teacher identity is used as actor, and server-side course ownership is checked before persistence.
- Added audit trace metadata to teaching operation receipts and persisted audit events: trace id, actor role, auth mode, operation/action/course, redacted request source, and storage policy are captured without exposing cookie/session values.
- Updated ordinary teaching UI failure closure: `/teaching` inline actions and `/teaching/[operation]` action buttons now surface a localized "not saved" failure message when the backend denies or fails the write.
- Added ordinary teaching operations production smoke coverage: `scripts/teaching-operations-route-smoke.mjs`, local-production plan coverage, production orchestrator step, and release-gate validation for the teaching operations route evidence.
- Added/updated tests for signed auth denial, course ownership denial, spoofed actor prevention, audit trace persistence, frontend authorization failure feedback, local/production route smoke plans, and release-gate teaching operations smoke validation.
- Added production persistence support for ordinary teaching operations: `UAIS_TEACHING_OPERATIONS_BACKEND=external` now sends authorized operation records and audit events to the external storage service instead of writing the local JSON database. External storage exposes `POST /teaching-operations/{teacherId}/append` in both the standalone service and Next-hosted route service.
- Tightened release evidence so teaching-operations production smoke must prove durable external persistence via `external-redacted-teaching-operation-append`; local-only persistence no longer satisfies that route-smoke requirement.
- Added fail-closed coverage: if external teaching-operation persistence is selected but the external storage env is missing or weak, `/api/teaching/operations` returns redacted `503` and does not write local operation/audit records.
- Added the first teaching-operation business-semantic projections: course settings saves now create a `course-settings` domain object, roster sync creates a `student-roster` domain object, and invite-code publication creates an `enrollment-access` domain object tied to the published code and join URL.
- Extended teaching-operation business projections for three more ordinary-management actions: knowledge-base sync now creates a `knowledge-index` domain object, content publishing creates a `course-content` domain object, and grading queue saves create a `grading-queue` domain object.
- Closed the first course-cover asset binding gap: `/api/teaching/course-cover` now stores a redacted `course-cover` asset record in a server-side teaching course asset database, keyed by the generated provider request id and course id, instead of only returning the generated image URL.
- Reduced AI direct-call risk for production contract mode: `/api/ai/chat`, `/api/ai/ppt-narration`, and `/api/ai/voice-sample` now require signed AI access in production even when `executionMode` is `contract`; live provider approval remains limited to live mode.
- Added backend course/class creation contracts for the main teaching workspace gap: `/api/teaching/courses` creates signed-teacher-owned course records, merges the new course id into teacher ownership scope, and rolls back the local course write if ownership merge fails; `/api/teaching/courses/[courseId]/classes` creates signed-teacher-owned class records with deterministic invitation codes under persisted courses.
- Added the first invite-code membership closure: `/api/teaching/invite-codes/[code]/join` lets a signed-in student app session redeem a persisted class invitation code into a pending `membership` record, with student-role audit metadata, trace id, redaction, and no-store responses.
- Added the teacher approval half of the invite-code membership closure: `/api/teaching/classes/[classId]/memberships/[membershipId]/approve` requires signed teacher auth, verifies class ownership, promotes pending memberships to `approved`, recalculates class/course student counts from approved memberships, and records traceable approval audit events.
- Extended the ordinary grading business semantics: grading review saves now also produce a `gradebook-update` domain projection with `pending-release` status and a teacher-confirmed release policy, so the backend records an actual gradebook update object instead of only a review-queue action.
- Extended the ordinary email/notification semantics: collaboration invites now also produce an `email-notification` domain projection tied to the server outbox item, with queued delivery status and a policy boundary before any future SMTP/provider handoff.
- Added the signed teacher gradebook release API: `/api/teaching/gradebook-updates/[objectId]/release` requires a signed teacher session, verifies course ownership, promotes a pending gradebook update to `released`, queues a grade-release notification projection, and writes a traceable `teaching-gradebook-update.released` audit event.
- Added the signed teacher gradebook release rollback API: `/api/teaching/gradebook-updates/[objectId]/rollback` requires a signed teacher session, verifies course ownership, changes released gradebook updates to `release-rolled-back`, queues a rollback notification projection, and writes a traceable `teaching-gradebook-update.release-rolled-back` audit event.
- Added a local backup safety step for ordinary teaching operations: before replacing an existing local `teaching-operations.json`, the store now writes a redacted pre-replace snapshot under `backups/` with fixed source-file metadata and no local path or secret leakage. This gives the local JSON persistence mode a verifiable backup artifact while the production external backend remains the durable path.
- Added process-local concurrency control for the local JSON fallback: ordinary teaching operation writes now serialize the full local read-modify-write path per resolved data directory, preventing simultaneous local button/API writes from overwriting each other's records in one server process.
- Added a signed restore drill endpoint for local teaching-operation backups: `/api/teaching/operations/backups/[backupId]/restore` requires a signed teacher session, verifies ownership for every course present in the selected backup, restores the local database snapshot, and appends a traceable `teaching-operations-backup.restored` audit event without exposing local paths.
- Tightened the restore endpoint safety boundary: when `UAIS_TEACHING_OPERATIONS_BACKEND=external`, the local backup restore endpoint now fails closed with a redacted `409` instead of pretending to restore the production durable operation log from a local JSON fallback file.
- Hardened `/api/teaching/course-cover`: cover generation now requires a signed teacher session and server-side ownership of the requested course before DashScope/Qwen is called, so the generated course-cover asset path is no longer an unauthenticated provider/API-key entrypoint.
- Added persisted course-cover audit events: successful `/api/teaching/course-cover` calls now write a `teaching-course-cover.generated` audit record with trace id, signed teacher actor, course id, request source, asset id, provider request id, storage policy, and redaction metadata alongside the generated cover asset.
- Extended the ordinary AI-agent management semantics: `agents` primary saves now create an `agent-plan` domain projection with enabled agent ids, teacher governance policy, course id, actor, source action, and operation record linkage instead of only recording that the button was clicked.
