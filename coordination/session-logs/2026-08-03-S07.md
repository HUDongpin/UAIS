### Audit that motivated this package

A 15-agent read-only audit of the chatroom stack (6 dimension reviewers + per-finding
adversarial verifiers) confirmed 9 problems, 0 refuted. Headline items: demo seed
transcript shown to real users AND sent to the model as genuine history; zero
persistence; hardcoded demo courseId no real membership can match; one oversized
paste bricking the session; no provider timeout; mid-round failure discarding
completed turns; no rate limiting; failures invisible to operators.

### Changes

Backend (src/app/api/learning/chatroom/route.ts, src/lib/ai/providers/deepseek-client.ts,
src/app/api/ai/chat/route.ts, src/app/api/learning/ai-guide/route.ts):
- Provider timeout: complete() takes timeoutMs (default 15000) via AbortSignal.timeout;
  timeouts throw the exported deepSeekTimeoutErrorMessage. Error bodies are read once
  as text and parsed defensively, so a non-JSON provider 502 no longer throws SyntaxError.
- Round budget: an absolute 50s request budget anchored at handler entry (so body-read
  and authorization time is charged), per-call timeout clamp(remaining-2000, 3000, 15000),
  and agents left without budget skip the provider and emit a localized timeout fallback.
  maxDuration = 60.
- Partial-failure resilience: a failing agent no longer discards the round; it contributes
  a locale-correct fallback turn and an entry in the new optional turnErrors array.
  All-failed rounds return 504 (any timeout) else 502.
- History sanitation: oversized OLD history messages are truncated to 4000 chars instead
  of failing the round; only an oversized LAST student message still rejects with 400.
- Status classes: 400 validation, 401 session, 403 access, 500 unexpected, 502 provider,
  503 config, 504 timeout. /api/ai/chat and /api/learning/ai-guide also map provider
  timeouts to 504 (they inherited the new default timeout).
- Observability: structured console.error("[learning-chatroom", {traceId, phase, courseId,
  agentId, message}) plus guarded Sentry.captureException tagged route:"learning-chatroom";
  no message content, cookies, or env values are logged. Every response (200 and error)
  carries the x-uais-trace-id header.

Frontend (src/components/pages/learning-page-chatroom.tsx, src/i18n/copy.ts):
- Real-course resolution from GET /api/teaching/courses: URL ?courseId=&classId= hint →
  prop hint → single usable course auto-select → course picker → demo fallback.
  Students resolve through APPROVED memberships (the same predicate the API authorizes on);
  teachers through owned courses. Active course renders as a chip that reopens the picker.
- The demo seed transcript now renders ONLY as a read-only preview in demo context and is
  never included in any API payload. Real courses start from the empty-chat placeholder.
- No lying fallback: a signed-in student with no usable courses gets a disabled composer
  and join/create guidance instead of a demo course that would 403 on every send; a failed
  courses fetch renders a distinct load-failed state (never "you have no courses").
- Sends are gated until resolution completes; switching courses resets the transcript
  (draft preserved); an in-flight round superseded by a course switch is discarded whole
  via a room token, so course A's reply can never land in (or be posted as history for)
  course B.
- Input capped at 4000 chars with a pre-send guard; 400 responses map to new
  request-invalid copy; agentAccessDenied rewritten as actionable join/create guidance.
- New copy keys (both locales): agentMessageTooLong, agentRequestInvalid,
  chatroomCoursePickerLabel, chatroomActiveCourseLabel, chatroomDemoCourseLabel,
  chatroomNoCourses (now superseded), chatroomJoinCoursePrompt, chatroomCourseLoadFailed.
