## Summary of work completed

Six client-side fixes plus a flake fix and one required test add. Concurrent engineers own the server (`route.ts`, `share/*`, `src/lib/server/*`) and two teaching test files; none of those were touched.

- **FIX 1 (MAJOR) — export always showed the "blocked" notice.** `use-learning-chatroom.ts` `handleExport` used `const opened = window.open(url, "_blank", "noopener")` and treated the return as a success signal, but `window.open(..., "noopener")` returns `null` even on success, so every export reported `exportBlocked`. Now fire-and-forget: open the first-party print route and set `t.learning.exported` unconditionally. `t.learning.exportBlocked` is simply no longer referenced from this file (copy.ts untouched).
- **FIX 2 (MAJOR) — agent turns could render twice.** `requestAgentTurns` appended POST-result turns with no dedupe; the 5s poll can merge the same server-minted turn id first, so the POST append duplicated React keys and doubled the reply. The append now builds a `Set` of current message ids and filters appended turns to unknown ids (mirrors `mergeRoomTranscript`), returning `current` unchanged when nothing new remains.
- **FIX 3 (flake) — five real-timer tests asserting exact history-GET counts.** Converted to `vi.useFakeTimers()` + the suite's own `settle()`/`getByText` pattern so the armed 5s poll interval can never fire an extra GET mid-assertion. Tests fixed: "auto-enters the only assigned group", "shows the group picker for two groups", "resolves a ?groupId= deep link", "stays quiet and legacy", "drops the group and re-reads the legacy room" (this last one uses three `settle()` cycles for its two-hop group→legacy re-read). `afterEach` already restores real timers via `vi.useRealTimers()`.
- **FIX 4 (MINOR) — composer stayed enabled + false learning record after a denied room.** `composerDisabled` now also folds in `roomAccessNotice !== null`, so a room the server refused (halted polling) accepts no send. The `collaboration.contributed` emission moved out of `handleSend` (where it fired optimistically, before any authorization outcome) into `requestAgentTurns` after `response.ok` — a refused send (401/403/400) or network failure now records nothing.
- **FIX 5 (MINOR) — duplicate React keys.** `RosterPanel` and `MemberFacepile` keyed rows by `${displayName}-${isSelf}`, which collide for two members sharing a display name (rosters carry names only by privacy design). Added the array index to the key (rosters are order-stable server snapshots).
- **FIX 6 (MINOR) — clipboard false success.** `handleShare` claimed `t.learning.copied` even when `navigator.clipboard` is absent (insecure context). Now branches on `!navigator.clipboard` → `t.learning.copiedFallback` (the link is still shown in the notice); the existing `catch → copiedFallback` is kept.
- **TEST ADD (§7 family 7) — reduced motion.** Added "keeps the thinking-indicator dots motion-safe for reduced motion" to the group-live suite: drives a deferred round to pending, then asserts the three thinking dots carry `motion-reduce:animate-none`.
