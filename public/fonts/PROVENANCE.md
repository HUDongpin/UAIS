# Font provenance (S24)

Assets here are embedded into server-generated PDFs. Every entry records where
the file came from, how it was derived, and under which licence, per AGENTS.md's
rule that `public/` assets carry documented provenance.

## NotoSansSC-GB2312-Regular.ttf

- Family: Noto Sans SC (Simplified Chinese), Regular (wght 400), **static, TrueType outlines**.
- Size: 2,254,452 bytes (2.15 MB)
- SHA-256: `c502e1a3112c2dc65775892f1d3aee5b8e2506b3e23896392e5a01a3dd78294a`
- Licence: SIL Open Font License 1.1 — full text in `NotoSansSC-OFL.txt`. OFL
  permits embedding, redistribution, subsetting and modification; it forbids
  selling the font alone and requires the licence to travel with it, which is
  why the licence file sits beside it here.
- Coverage: the GB2312 repertoire (6,763 hanzi) plus ASCII, Latin-1, general and
  CJK punctuation, and fullwidth forms — 7,904 characters in total. The exact
  set is checked in beside it as `NotoSansSC-GB2312-charset.txt`.

### Derivation (reproducible)

Not a downloaded artefact — derived from two upstream sources:

1. Variable source: `https://raw.githubusercontent.com/google/fonts/main/ofl/notosanssc/NotoSansSC[wght].ttf`
   (16.95 MB, retrieved 2026-08-09).
2. Licence: `https://raw.githubusercontent.com/google/fonts/main/ofl/notosanssc/OFL.txt`.

```bash
# fontTools 4.63.0 in a throwaway venv; not a project dependency.
fonttools varLib.instancer "NotoSansSC[wght].ttf" wght=400 -o NotoSansSC-static.ttf
pyftsubset NotoSansSC-static.ttf \
  --text-file=NotoSansSC-GB2312-charset.txt \
  --output-file=NotoSansSC-GB2312-Regular.ttf \
  --layout-features='' --no-hinting --desubroutinize --drop-tables+=DSIG
```

The charset file is generated by enumerating every character the `gb2312` codec
can encode (lead and trail bytes `0xA1`–`0xFE` inclusive) and adding ASCII,
Latin-1, `U+2000–U+206F`, `U+3000–U+303F` and `U+FF00–U+FFEF`.

### Why subset on disk rather than at runtime

pdf-lib exposes `embedFont(bytes, { subset: true })`, which would let us ship the
full face and emit tiny PDFs. It was measured against this font and **it does not
work for CJK**: the output opens, text extraction is perfect, and the page still
renders blanks and mojibake, because the emitted font program is incomplete —
`pdftoppm` reports `Couldn't create a font` / `non-embedded font using identity
encoding`. The same held for the full CFF/OTF face, the variable TTF, and a
static TTF instance. Only `subset: false` renders correctly, so the subsetting
had to move to build time, which is what this file is.

Consequence: a generated transcript PDF is roughly 1.5 MB, nearly all of it the
embedded face. That is the price of a self-contained document that renders
Chinese on any reader, on any machine, with no font installed.

### Known limit

A character outside GB2312 — a rare or variant hanzi, a personal name using an
uncommon character, traditional-only forms, or any non-CJK script beyond
Latin-1 — has no glyph and will not draw. Widening to the full GBK repertoire
(22,228 characters) was measured at 7.12 MB, which would have tripled every
exported PDF; GB2312 covers standard modern Simplified Chinese, including the
common name characters spot-checked during the decision (宁, 淼, 昊). If missing
glyphs are reported in practice, regenerate with a GBK charset using the same
two commands above and update the size, hash and this note.

Deployment note: `next.config.ts` names this file in `outputFileTracingIncludes`
for the PDF route, because the runtime reads it from disk and Next's tracer
cannot infer a `process.cwd()`-relative read on its own.
