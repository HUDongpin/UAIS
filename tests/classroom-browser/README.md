# Isolated classroom acceptance

Run `npm run test:classroom` from the repository root. The runner creates a fresh loopback Postgres database, applies local migrations, seeds only a synthetic teacher, disables provider credentials, builds and starts the local application, then invokes `playwright.classroom.config.ts`. Local PostgreSQL commands and the project's installed Playwright browser are required. It never needs production credentials or an external deployment.

For interactive diagnosis, `npm run test:classroom -- --dev --serve` keeps an isolated development server running. `UAIS_CLASSROOM_FIXTURE_PATH` may then be supplied to `npx playwright test --config=playwright.classroom.config.ts`. Keep the fixture private: it contains only synthetic test credentials, but neither it nor browser cookies belong in reports, screenshots or commits. The test refuses a non-loopback URL, a different database name, or a database without the `isolated-classroom-pilot` guard. Do not use ordinary deployment environment variables to point this suite at staging or production.

The default journey creates a new course and class through the teacher interface, imports and edits both real mathematics JSON packages, publishes their tasks, previews and imports a 30-student CSV, and activates students. A barrier waits until all 30 accounts are ready before 28 HTTP admission requests and two real browser admission clicks begin concurrently. Two independent browser sessions exercise first-login UI, invite join, lesson navigation, formative work, text/image submission and released teacher feedback after re-login. Authenticated HTTP clients exercise the other first-lesson submissions and all 30 second-lesson submissions concurrently. The suite reads the actual database only to validate environment isolation and reconcile successful receipts; it does not seed lessons, members, student accounts, submissions or feedback directly.

Further checks cover old-task lesson-version pinning after V2 publication, teacher-only material exclusion, private-image denials, ten discussion groups, cross-group read denial, and a pending image restored from browser storage after an offline refresh. Messages contain no AI mentions and request no live provider round.

`npm run test:classroom -- --soak-minutes 90` additionally performs a real 90-minute, 30-actor history-read soak at 2.5-second rounds. The default reports this soak as unverified. During the extended run, `summary.json` updates `extendedSoak` every 30 seconds with elapsed minutes (one decimal), completed rounds, successful reads and `actors:30`. `verified` remains false until all 90 minutes and runtime checks finish successfully; no per-request console output or actor identifiers are included. A short successful run does not prove continuous classroom operation.

Evidence is allowlisted into `output/classroom-pilot/summary.json` and selected screenshots. Traces, video, raw error logs, automatic failure screenshots and storage-state files are disabled. The custom reporter prints known phase names, statuses and elapsed time. Summary files record counts, operation durations, completed phases and safe failure locations; no credentials, cookies or request bodies are persisted. Screenshots are taken only on non-authentication teaching or feedback screens after initial credentials have been cleared.

The p95 threshold is 2 seconds for ordinary save, seal, chat-read and chat-send HTTP requests; image uploads are reported separately. Development compilation can affect these measurements. A loopback result is not production latency or acceptance by real teachers and students. Production migration/deployment and formal small-class use remain separate steps.

Compiled local builds set `Secure` cookies. Chromium permits those cookies on trustworthy loopback HTTP, while Playwright's API cookie jar does not send them automatically. The test HTTP helper therefore reads its own cookie jar in memory and explicitly carries the same server-issued signed cookies to the bound `127.0.0.1` origin only. It does not forge sessions, change application cookie settings, persist cookies, or allow remote targets. Browser UI traffic still follows Chromium's native cookie policy; this transport accommodation does not test HTTPS/TLS deployment configuration.
