# UAIS 小班课堂操作说明

适用：一位教师、约 30 名学生、两个 45 分钟课时。以下步骤使用当前课堂入口；生产迁移与部署、导入真实名单、正式课堂试用需由项目负责人安排。第一次试用先使用隔离环境中的测试账号，不把隔离演练通过视为生产验收。

## 教师：准备、发课和评阅

1. 登录 `/login`，进入 `/teaching`。在课堂工作台选择自己的课程，或“创建课堂课程”；在“学生与班级”创建班级。
2. 准备 CSV，列名为 `account,displayName,email`，邮箱列可省略。账号可用字母、数字、点、下划线和连字符，不能含空格；请先选择稳定且不会与别班学生混淆的账号。每次最多 100 人、100 KB，不添加密码或角色列。
3. 在当前班级的“学生账号与首次登录”选择 CSV，“预览名单”后检查新增、已有、重复与无效记录。修正全部错误后确认创建。已有学生账号继续使用原密码，原有课程关系不会被改写；同名教师或不匹配的身份会被拒绝。
4. 下载或打印本次新账号的初始凭据，**把每人的凭据分别交给本人**。不要把整班凭据贴到群聊或公共屏幕。凭据只在本次响应中提供，离开页面不能读回；自己创建且尚未设密的账号可以补发新凭据，补发会立刻使旧凭据和旧设密会话失效。
5. 通过“查看班级邀请码”提供入班方式。学生完成设密并申请入班后，在同一班级的成员列表批准申请；账号创建本身不会自动授予课程访问权。按课堂需要建立小组。
6. 在“课时与任务”选择 `data/classroom-lessons/01-natural-numbers.json` 和 `02-induction.json`，预览并导入草稿。依次检查内容与独立教师指南；保存修改，选择班级和附带任务，查看学生预览，再确认发布。
7. 在“提交与反馈”进入任务与提交队列。阅读学生文字、图片及版本，按三项量规判断，保存或发布反馈，必要时要求修订。只有已经发布的反馈才按权限显示给学生；AI 关闭时手工评阅仍可完成。
8. 在“课堂讨论”进入当前班级讨论。对需要保留的课堂过程，可导出记录；不要把仅有近期消息的屏幕误当作整段讨论。

两个数学课时包含教师答案，不直接发原始 JSON 给学生。学生通过已发布课时阅读允许访问的材料。再次发布会形成新版本；旧任务、提交和反馈继续保留原依据。

CSV 示例（仅为格式示意，使用前换成隔离测试身份或经批准的真实名单）：

```csv
account,displayName
class-demo-01,测试学生甲
class-demo-02,测试学生乙
```

## 学生：首次登录、入班与提交

1. 在 `/login` 输入教师单独发给你的账号与初始凭据。新账号会进入 `/first-login`，先设置 12–128 个字符的新密码，且不能与初始凭据相同。初始凭据不能直接进入学习区；设密会话 15 分钟有效，过期后用最新初始凭据重新登录。
2. 按教师提供的邀请码或入班链接申请加入班级。等待教师批准，然后从课程进入课堂学习，选择相应课时，阅读材料并打开本课任务。
3. 完成形成性检查，再准备自己的答案。可以用文字、手写图片或组合；每个提交版本最多 3 张 PNG/JPEG，每张不超过 1 MiB。只拍自己的作业，检查符号清晰，不上传同学的人脸或个人资料。
4. 等待保存和图片上传确认，再提交。区分“草稿已保存”“已提交”和“结果待确认”；出现待确认时先读取服务端状态，不要把一次网络错误当作数据已丢失。
5. 如果断网，保留当前页面，等待恢复后重试。未确认图片会尝试在本机浏览器暂存；浏览器存储不可用时以页面提示为准，不能把本地未确认内容当作服务端已保存。公共电脑使用后退出账号，并避免留下作业副本。
6. 重新登录后回到同一课时与任务，查看已确认保存的提交和教师已发布的反馈。若教师要求修订，提交新版本，并简述改了什么。

## 课堂中出现问题

| 看到的情况 | 处理方法 |
|---|---|
| 初始凭据失效 | 确认是否已经设置个人密码或教师曾补发；已激活账号使用个人密码，未激活账号可请原导入教师补发。此功能不提供全站账号接管或任意重置。 |
| 已登录但看不到课时 | 检查是否进入正确班级、入班申请是否批准、教师是否向该班发布课时；不要用其他班级链接替代授权。 |
| 发布或保存发生冲突 | 保留当前文字，按提示重新读取服务端版本后再合并，避免覆盖另一窗口的修改。 |
| 上传未确认或失败 | 暂不封存提交，恢复连接后重试或明确移除失败图片；先确认文字草稿的状态。 |
| 提交响应丢失 | 保留当前任务页面，按“结果待确认”流程读回；不要反复新开任务重复提交。 |
| 聊天显示同步暂停 | 检查网络或等待限流恢复；暂停期间屏幕上的旧消息不代表没有新消息。 |
| AI 无法使用 | 继续阅读、讨论、保存、提交与教师手工反馈；本次数学示例默认关闭任务 AI。 |

## 课程结束与记录

记录保留与清理仅在课程和聊天均使用 Postgres 存储时可用；external 或 local JSON 环境会提示管理员配置并拒绝执行，不能把未清理的外部副本记为已清理。

课程负责人在“课程记录保留”选择“结束课程并开始保留期”，核对后“确认结束课程”，系统记录结束日期及 **180 天**后的保留截止日。保留期间，讨论、作业、图片和反馈仍按原有权限回看。到期后通过“预览到期清理”查看范围，再由负责人明确确认“清理本课程到期记录”；“结束课程”本身不立即删除课堂记录。

应用内清理与数据库备份的保存期、恢复后的再清理是不同操作。备份规则应按实际部署核实，不把应用记录清理描述为备份同步永久删除。导出到个人设备的文件也不会被服务器清理自动删除。

每次正式课堂前至少用教师及两个不同组学生账号走完：导入两课、发布、入班批准、文字/图片提交、教师反馈、退出重登读回。并发、权限、持续聊天与性能检查由验收记录单独提供；本操作说明不是测试通过证明。
